# Changelog

Generated by `tools/changelog.py` from `changes/` and each recipe's golden set and test report; do not edit by hand.
Every change that affects a recipe is here, dated, newest first.

## 2026-10-28: n8n prompt fill

- Fixed the n8n AI step's prompt builder: a filled-in value that itself looks like a placeholder, such as "{{line_3_total}}", is now sent to the model as written instead of being blanked.
- Only R5.3 was affected: its model was told "Placeholders you may use:" with an empty list, so it could not name the placeholders the quote step fills; its n8n workflow is updated and passes its golden set.
- The other 24 n8n builds with an AI step send the same prompts as before; all 25 golden sets were run again and pass.
- The R5.3 Make build still has the old prompt builder; its fix ships with the next Make test run.
- The n8n test runner takes `--case` to run only some cases while debugging, as the Make runner does.

## 2026-10-28: make ai builds

- Added Make builds for 16 more recipes with an AI step: R4.2, R4.4, R5.1, R5.2, R5.3, R6.1, R6.2, R7.1, R7.4, R9.1, R9.2, R10.1, R10.2, R10.3, R12.2 and R14.1.
- Every golden-set case of these recipes passes on Make (cloud service, Core plan), including the cases that need Claude Haiku 5.5's live answer.
- Where a recipe's spec tries an AI call or a read three times, the Make build does too.
- The Make test runner now sends the mocks' seed data through the public test route, so a seed that names a mock URL reaches Make, and it no longer misses a run that Make's log listing showed only briefly.
- Known issue: the R5.3 prompt builder drops text such as "{{name}}" when it appears inside a filled-in value; a fix for both the n8n and Make builds follows.

## 2026-10-27: make rules only complete

- Added Make builds for the remaining rules-only recipes: R7.3, R8.1, R9.4, R11.3, R12.3, R13.2 and R15.3, each passing its whole golden set on Make (cloud service, Core plan); every recipe with no AI step now has a tested Make build.
- Fixed text in a Make Config step that holds merge fields, such as R8.1's reminder templates and R8.2's statement subject: Make reads `{{...}}` in a Code step as its own mapping and blanked them, so a brace followed by a brace is now written as `\u007b`, which reads back as the same text. R8.2's Make build was rerun and passes; its earlier blueprints sent statements with an empty subject.
- Reran R11.2's Make golden set on the current builder: all 8 cases pass.

## 2026-10-27: make ai step

- Added the first Make build with an AI step, R4.1: all 8 golden-set cases pass on Make (cloud service, Core plan), including the cases that need Claude Haiku 5.5's live answer.
- A Make AI step sends the prompt file's request with your own Anthropic API key, held in a Make HTTP "API key" connection; the blueprint carries no key, and README step 6 says how to connect yours. A failed call is tried once more, and a second failure sends the item to the safe path, as in the n8n builds.
- Make scenarios now open with no two modules on the same spot: error routes from neighbouring steps were drawn over each other. Only module positions changed; every step, mapping and filter is as tested.

## 2026-10-26: make rules only builds

- Added Make builds for seven more rules-only recipes: R5.4, R8.2, R9.3, R12.1, R14.2, R14.3 and R15.2, each generated by `tools/builds_make/` and passing its whole golden set on Make (cloud service, Core plan); each run's result and credits are in the recipe's `make/test-report.md`.
- A recipe with several triggers has one Make scenario per trigger: `make/blueprint.json` for its main event and a named file for each other one, such as `make/decision.blueprint.json` or `make/morning.blueprint.json`.
- R12.1's Make build reads its cut-off weekday and time in UTC, because Make's Code app has no time-zone library; its Config step says so.
- R14.2's Make build reads the action list once more before step 8, because Make cannot gather one message per owner across separate routes.
- Added the key log's table-API functions to `patterns/duplicate-check/schema.sql`: `reserve_key` can reopen a done key, and `reserve_keys`, `finish_keys`, `release_key`, `release_keys_for` and `add_exception_once` do the n8n builds' other key-log statements, so the table API never needs delete rights.
- The Make golden-set runner loads every recipe into five kept test scenarios instead of creating scenarios on each run, because Make limits how many scenarios a team may create.

## 2026-10-25: phase 3 make pilot

- Added the first Make build, R11.2: `recipes/R11.2/make/blueprint.json` (the request check, started by a webhook) and `make/backstop.blueprint.json` (the morning backstop, a scheduled scenario), generated by `tools/builds_make/r11_2.py`.
- The Make build runs the n8n build's own rule JavaScript, and its golden set is the n8n one: all 8 cases passed on Make (cloud service, Core plan) on 2026-10-25, using 112 credits (`make/test-report.md`).
- Reads use Make's Retry handler, and failed writes go to an error route that marks the key failed, adds an exception-queue row and ends with the Skip handler, as in Table 16.2 of the book.
- Added `reserve_key` to `patterns/duplicate-check/schema.sql`: the duplicate check as a function, for platforms that reach the tables over a table API instead of a database connection.
- The test stack (`tools/stack/`) adds PostgREST, the table API the Make builds use.

## 2026-10-20: phase 2 n8n builds

- Added a tested n8n build for every recipe: `recipes/<ID>/n8n/workflow.json`, generated by `tools/builds/` and run against the recipe's golden set on n8n 2.42.7 (self-hosted) with the mock systems in `tools/mock-systems/`; each run's result is in `n8n/test-report.md`, and the AI cases ran on Claude Haiku 5.5.
- Every workflow has the book's stop flag (Chapter 3) after its Config node; an unreadable stop list stops the run with an exception-queue row.
- Added `patterns/duplicate-check/schema.sql`: the key log, decision log and exception queue as Postgres tables, with a key column that refuses a second copy in the same step.
- Extended the golden sets with the failure paths each recipe's failure table names, an AI-error case for every AI recipe, and a "Stop flag" case; each extension is a row ending "(companion extension)" (see "Recipe status" below).
- Refuse rows whose bad output a well-behaved model will not produce are now tested with that exact output injected, and each is paired with a live-model row showing the model refuses.
- R7.1 returns each invoice line as description, quantity, unit price and amount (the book prints amounts only) so that R7.2 can pair lines; see the note in `recipes/R7.1/build-spec.md`.
- Prompt changes found by running the golden sets on the live model: R4.3 (write GAP without brackets), R5.2 (claim and criterion shapes), R5.3 (no numbered lines), R6.2 (never-say phrases passed with the input), R7.4 (no worked-out numbers), R9.2 (when a question is about the asker), R10.1 to R10.3 (mask token passed with the input), R12.2 (sentence and number shape), R15.1 (rules apply to subject lines; scan words; use each listed claim), R15.1 list-claims (each claim carries its type).
- Every prompt's output schema is now sent with its instructions, and AI calls allow 4,096 tokens, because Claude Haiku 5.5 thinks before it answers and a low cap stopped replies before any JSON.
